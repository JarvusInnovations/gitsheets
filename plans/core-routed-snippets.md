# Plan: route the Node Template and normalizeRecord through the core

Closes #373.

## Scope

On the Node binding the exported `Template` (and so `Sheet.pathForRecord`)
and `Sheet.normalizeRecord`'s comparators ran host-side in a `node:vm` realm
held to the core's determinism rule by a hand-written shim
(`packages/gitsheets/src/sandbox.ts`). Every boa or V8 upgrade was a new
chance for that path and the write path to disagree. This plan removes the
host realm:

- `Template.render` / `pathForRecord` render in the core
  (`CompiledDefinition.renderPath`).
- `Template.queryTree` keeps its JS tree walk but renders each component in
  the core in partial-query mode (a new per-component core call).
- `Sheet.normalizeRecord` runs the core's normalization (`SortPlan`, the
  code `Sheet::normalize_record` and every write run), retiring
  `buildSorter`, the host `localeCompare` for `sort = true`, the generated-JS
  directives, and `sort-keys`.
- `sandbox.ts` and every non-test `node:vm` import under
  `packages/gitsheets/src` are deleted, with a test that keeps them gone.

Out of scope: changing the napi marshalling rules (see the invalid-`Date`
follow-up); typed errors for marshal failures on the write path.

## Implements

- `specs/rust-core.md` — "Shipped status" (both halves live in the core) and
  "One realm, no host copy".
- `specs/behaviors/path-templates.md` — "Rendering" (core on every path,
  stringification, marshal failures), the bare-datetime rule, "Caching"
  (per thread).
- `specs/behaviors/normalization.md` — `sort = true` is the ICU collator on
  every path; "Normalization runs on the marshalled record".
- `specs/api/sheet.md` — `pathForRecord`, `normalizeRecord`.
- `specs/architecture.md` — no `sort-keys`.

## Approach

1. **Core** — `Template::render_component_partial(index, query, engine)` and
   `Template::is_recursive_component(index)` (path_template.rs), reusing the
   non-strict `render_component` that `plan_query` uses. Extract the sheet's
   sort plan into a public `SortPlan { compile(config, engine), apply(record,
   engine) }` (sheet.rs); `Sheet::open` / `Sheet::normalize_record` use it, so
   there is one normalization implementation.
2. **napi** — `CompiledDefinition` gains `componentCount`,
   `isRecursiveComponent`, `renderComponent(index, query) → string | null`,
   `fieldNames`, `staticFieldNames`. New class `CompiledSortPlan(configToml,
   configPath)` with `normalize(record)`. Typings regenerated by the build.
3. **Node** — `path-template/index.ts` becomes a wrapper: `fromString`
   compiles a `CompiledDefinition` (module-level cache, so per isolate /
   worker thread); `render` and `queryTree` steps call it; marshal failures map
   to `PathTemplateError(path_render_failed)`; `queryTree` strips
   function-valued query entries (as `Sheet.query` does). `sheet.ts` keeps the
   config TOML per parsed config (`WeakMap`) and compiles one
   `CompiledSortPlan` per Sheet per config; `normalizeRecord` maps marshal
   failures to `ValidationError(validation_failed)`. Delete `sandbox.ts`;
   `npm uninstall -w gitsheets sort-keys` (the core value already comes back
   key-sorted; JS's integer-key-first ordering is the same as `sort-keys`
   produced).
4. **Tests** — convert `snippet-determinism.test.ts` to single-engine
   assertions through the public API (no shim import), keep the determinism
   denials; add write-path ≡ `pathForRecord` / `normalizeRecord` regression
   tests (expression templates; raw-JS, directive, and `sort = true`
   comparators); a worker-thread render test; a guard test that fails if
   `sandbox.ts` exists or a non-test source imports `node:vm`.

## Behavior changes

Each is in `docs/migration-guide.md` (v2.13 → v2.14). Before = the `node:vm`
path; after = the core (which the write path already used).

- **Bare datetime field** — `Template.fromString('${{ at }}').render({ at:
  new Date(0) })`: before `"Thu Jan 01 1970 00:00:00 GMT+0000 (Coordinated
  Universal Time)"` (host zone dependent), after `PathTemplateError
  path_render_failed`.
- **Float / bigint field formatting** — `{ x: 1e21 }`: before `1e+21`, after
  `1000000000000000000000`; `1e-7`: `1e-7` → `0.0000001`; `Infinity`:
  `Infinity` → `inf`; `2n ** 70n`: `1180591620717411303424` → render failure
  (outside i64).
- **Unrepresentable values anywhere in the record** — `render({ x: 'a', f() {}
  })`: before `"a"`, after `PathTemplateError path_render_failed` ("cannot
  marshal JS value of type Function"); same for a symbol, a `null` array
  element. `normalizeRecord({ slug: 'a', f() {} })`: before returned the
  record with `f` kept, after `ValidationError validation_failed`.
- **normalizeRecord returns the core's value** — `{ slug: 'a', z: null,
  nest: { a: undefined, b: 2 } }`: before `{ nest: { a: undefined, b: 2 },
  slug: 'a', z: null }`, after `{ nest: { b: 2 }, slug: 'a' }`; `{ n: 5n }`:
  `5n` → `5`; class instances → plain objects (inherited enumerable
  properties included, which the vm copy skipped); `Date`s are new objects.
- **`sort = true` authority** — ordering from the pinned ICU collator instead
  of the host's `Intl` `localeCompare`. Same for ordinary input
  (`['b','B','a10','a9','É','e']` → `['a9','a10','b','B','É','e']` both ways);
  can differ only where the host ICU version differs from the pinned one.
- **Comparator algorithm** — the core's stable insertion sort instead of V8's
  `Array#sort`; identical for consistent comparators, can differ for
  inconsistent ones (now matching the write path).
- **Invalid `Date`** — the napi marshaller turns `new Date(NaN)` into the
  epoch (pre-existing, write path included). `${{ d: YYYY/MM/DD }}` with an
  invalid `Date`: before `path_render_failed` ("is an invalid Date"), after
  `1970/01/01`; `${{ d.getTime() }}`: `NaN` → `0`. Not papered over in host
  code; follow-up below.
- **`queryTree` with unrepresentable query values** — function entries are
  dropped (they never pruned; unchanged result); any other unrepresentable
  value (symbol, `null` array element) now throws `path_render_failed`
  instead of widening.
- **Template parse errors** — same classes and codes; messages now come
  from the core (e.g. a bad expression's message names boa's SyntaxError).

## Release order

This changes `gitsheets-core` (`SortPlan`, `render_component_partial`) and
the napi surface, and the JS package calls the new napi methods. CI's
`publish-npm` resolves the **published** platform binaries, so: merge →
tag `core-napi-v0.11.0` on develop (un-bumped manifests; the version is
tag-stamped) → wait for the 7 packages → PR the manifest/lockfile sync
(`packages/gitsheets` dep `^0.11.0`) → merge → JS `Release: v2.14.0`. The
`py-v*` track needs no bump for this (no Python surface change), but its
build runs the changed core.
